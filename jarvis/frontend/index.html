Settings

Model, key, and what JARVIS remembers

Cloud model

Streams a readable summary above the answer. Needs a model that supports it.
The model may ask to run a local function, such as searching past conversations. Tools run on this machine; only their results are sent.
If the model declines a request, the API retries it on another model in the same call. Turn off if your account rejects the beta.
Writes a line per request to logs/jarvis.log naming the context used. Useful while developing; leave it off afterwards, because it puts personal context in a file.
Off means memory is only ever written when you ask for it, or by hand on the Memory page.

Voice

Adds a microphone to the composer and speaks answers back.

Speech recognition and playback run in the browser through the Web Speech API. It costs nothing, needs no key, and the audio never reaches the server — only the transcribed text does. Chrome and Edge support it; Firefox does not, and the microphone stays hidden there. Swapping in a local model or a cloud service later is one registration in jarvis/voice/registry.py.

The key is read from the environment and never written to the database, so no copy of data/ can carry it. Set it in jarvis/.env as JARVIS_ANTHROPIC_API_KEY and restart JARVIS. There is no endpoint that returns the key to this page, on purpose.
